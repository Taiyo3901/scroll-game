## 1. どんなゲームか

### コンセプト

下にスクロールすると地面を掘り進み、スクロールを止めると鉱石が掘れるゲームです。普段どおりWebページを読むだけで遊べます。掘った鉱石は図鑑に集まり、フレンドとランキングや図鑑を比べられます。

### 狙い（設計で迷ったときの判断基準）

- SNSなどの無限スクロールは、ランダムなご褒美で指を止めさせない作りになっている。このゲームは同じ仕組みを逆向きに使い、「止まったとき」にご褒美を出す。
- 一番得をする遊び方が「ちゃんと読んで、読み終えたら手を止める」になるようにする。流し読みや、放置して稼ぐ遊び方では得をしないようにする。
- スクロール量が多い人ほど有利になる仕組みは作らない（ランキングも含む）。
- 見たページのURL・タイトル・本文は保存も送信もしない。

迷ったら、この狙いに沿う方を選んでください。

### 作らない機能

- 第一発見者の称号
- 鉱石の交換

## 2. 技術スタック

- Chrome拡張機能 Manifest V3
- TypeScript、Vite（拡張機能向けのViteプラグインを使ってよい。選定理由を計画で説明すること）
- ポップアップ、図鑑ページ、ランキングページ：React（または同等の軽量なもの）
- 画面右端の演出（content script）：フレームワークを使わず、素のTypeScriptとShadow DOMで作る（ページを重くしないため）
- テスト：判定ロジックなどの純粋な関数は Vitest で単体テストする
- オンライン機能：Firebase（無料のSparkプラン）の Authentication と Cloud Firestore。Cloud Functions はSparkプランでは使えないため使わない
- MV3では外部からのコード読み込みが禁止されているため、ライブラリはすべてビルドに同梱する

## 3. 構成要素

| 要素 | 役割 |

| service worker | 状態の保存と集計、バッジ更新、離席判定（`chrome.idle`）、定期処理（`chrome.alarms`）、Firebaseとの同期 |

| 図鑑ページ | 拡張機能内のページ（タブで開く）。図鑑、標本棚、記録 |
| ランキングページ | 拡張機能内のページ（タブで開く）。ランキング、ユーザー選択、図鑑比べ、フレンド管理 |
| 設定 | ポップアップ内、またはオプションページ |

## 4. ゲーム仕様

### 4.1 状態

- プレイヤーの状態は「探検中」と「地上」の2つ。
- 深度は累積で、探検ごとにリセットしない。次の探検は前回の続きから始まる。
- バッグ：探検中に掘った鉱石が入る。地上に戻ると図鑑に登録される。
- ランタンの油：0〜100。

### 4.2 スクロール計測

- content script で、`document` に `capture: true` で `scroll` イベントを登録し、ページ全体のスクロールと、ページ内の枠（Gmailなど）のスクロールの両方を拾う。要素ごとに前回のスクロール位置を `WeakMap` で持ち、差分を計算する。
- 数えるのは下方向のみ。上方向は無視する。
- ユーザーの操作（`wheel`、`touchmove`、`keydown`、`pointerdown`）から一定時間（初期値1秒）以内のスクロールだけを数える。ページ内リンクのジャンプやサイト側の自動スクロールは数えない。
- 換算：CSSの1px = 1/96インチ ≒ 0.2646mm。ゲーム内の深度 = 換算した実際の距離 × `DEPTH_MULTIPLIER`。
- イベントリスナーは passive にし、イベント内で重い処理をしない。距離は content script でためて、数秒ごとにまとめて service worker に送る。
- トップフレームでのみ動かす（iframe は対象外）。

### 4.3 流し読み判定

- 一瞬の速さではなく、一定時間の平均で判定する。丁寧に読む人も、読み終えた直後は1画面分を素早くスクロールするため、瞬間の速さでは区別できない。
- 直近 `SKIM_WINDOW_SEC`（初期値10秒）のスクロール距離が、画面の高さ × `SKIM_SCREENS`（初期値1.5）を超えたら「流し読み状態」とする。
- 流し読み状態の間は、深度に数えず、採掘も始まらない。
- 流し読み状態が終わってから `SKIM_COOLDOWN_SEC`（初期値5秒）は採掘できない。
- 流し読みと判定された距離も、統計としては記録する（流し読み率を出すため。4.11参照）。

### 4.4 採掘

開始条件（すべて満たすとき）：

1. 探検中である
2. 最後のスクロールから `MINING_START_DELAY_SEC`（初期値3秒）たっている
3. 流し読み状態でなく、クールダウン中でもない
4. タブが表示中（`document.visibilityState === 'visible'`）で、ウィンドウが前面にある（`document.hasFocus()`）
5. `chrome.idle` の状態が `active`
6. 画面内にある程度の文字が表示されている（`MIN_VISIBLE_TEXT_CHARS`、初期値200文字）。画面上の格子状の点で `document.elementFromPoint` を使って要素を集め、文字数を概算するなど、軽い方法で判定する。動画だけ、画像だけの画面では掘れないようにする
7. その画面位置でまだ掘っていない
8. 今日の採掘回数が `MAX_MINES_PER_DAY` 未満

進行：

- 条件を満たすと採掘が始まり、`MINING_DURATION_SEC`（初期値8秒）かけて採掘ゲージがたまる。
- 途中でスクロールしたり条件を外れたりしたら中断し、ゲージはリセットする。
- ゲージが満タンになったら、現在の地層の鉱石を抽選してバッグに入れる。
- 「掘った場所」は、スクロールしている要素と、スクロール位置を画面の高さ単位で丸めた値の組で記録する。この記録はそのページを開いている間のメモリだけに置き、保存しない（URLを残さないため）。

### 4.5 ランタンの油と帰還

- 油の消費：採掘1回で `OIL_PER_MINE`（初期値10）。掘り進む距離でも少し減る（`OIL_PER_METER`）。
- 地上に戻る方法は2つ。ポップアップの「地上に戻る」ボタンを押す。または `AUTO_RETURN_MIN`（初期値5分）スクロールしない・離席したときに自動で戻る。どちらの場合も、バッグの鉱石はすべて図鑑に登録される（「自分で戻った」として記録する）。
- 油が0になったら強制帰還となり、バッグの鉱石の半分（切り捨て、ランダムに選ぶ）を失う。
- 地上にいる間、油は `OIL_RECOVER_PER_MIN` ずつ回復する（初期値は約15分で満タンになる量）。
- 地上にいて油が `START_OIL_MIN`（初期値30）以上あれば、下にスクロールすると自動で探検を再開する。足りなければスクロールしても何も起きず、右端に「油を補充中」と表示する。
- 1日の採掘回数には上限 `MAX_MINES_PER_DAY` を設ける。ゲーム自体にハマりすぎないためと、ランキングの不正値を見分ける基準にするため。

### 4.6 地層と鉱石

- データは `src/data/strata.json`（地層）と `src/data/ores.json`（鉱石）に分け、後から編集しやすくする。
- 地層ごとに、境界の深度、名前、右端の帯に使う色を持つ。
- レア度は★1〜★3。抽選の重みは初期値で★1が70、★2が25、★3が5。
- ポイントは★1が1点、★2が3点、★3が10点。

初期データ（深度の境界は仮の値。`DEPTH_MULTIPLIER` と合わせて調整する）：

| 地層 | 深度（仮） | ★1 | ★2 | ★3 |
|---|---|---|---|---|
| 表土 | 0〜50m | 小石 | 土器のかけら | 古銭 |
| 第四紀 | 50〜150m | 石英 | 砂金 | マンモスの牙 |
| 新第三紀 | 150〜400m | 黄鉄鉱 | 葉の化石 | メガロドンの歯 |
| 白亜紀 | 400〜800m | アンモナイトの化石 | 琥珀 | 恐竜の歯 |
| ジュラ紀 | 800〜1500m | 珪化木 | 魚竜の骨 | 始祖鳥の羽の化石 |
| 古生代 | 1500m〜 | ウミユリの化石 | 三葉虫の化石 | 翡翠 |

各鉱石には、図鑑で読める短い解説文（2〜3文）を付ける。明らかな事実の誤りは避けること。

### 4.7 画面右端の演出

- content script で `position: fixed` の細い帯を挿入する。位置は、画面右端からスクロールバーの幅（`window.innerWidth - document.documentElement.clientWidth`）だけ内側。帯の幅は約44px。
- `pointer-events: none` にして、クリックやスクロールバーの操作を邪魔しない。Shadow DOM で包み、サイトのCSSと干渉しないようにする。`z-index` は最大値。
- 表示する内容：
  - 現在の深度
  - 地層の色（深くなるほど変わる）
  - 採掘中のツルハシの動きと採掘ゲージ
  - 鉱石を掘り当てたときの小さな演出（★3は少し派手に）
  - ランタンの油の残量（少なくなると明かりがちらつく）
  - 流し読み状態の表示（ツルハシが空振りする、など）
- アニメーションは `transform` と `opacity` だけで作る。動きがないときは `requestAnimationFrame` を止める。`prefers-reduced-motion` が有効なら動きを控えめにする。
- 設定で演出をオフにできる。また、特定のサイトで無効にできる（ユーザーが自分で登録したホスト名のみ。ローカルにだけ保存する）。
- ページのレイアウトや操作に影響を与えないこと。

### 4.8 バッジ

- `chrome.action.setBadgeText` で深度を表示する（例：「320m」「1.2k」）。
- 地上、探検中、油切れ間近で背景色を変える。

### 4.9 ポップアップ

- 現在の深度と地層、油の残量、バッグの中身、今日の採掘回数
- 「地上に戻る」ボタン
- 図鑑ページ、ランキングページを開くボタン
- 右端の演出のオン・オフ

### 4.10 図鑑ページ

- 地層ごとに鉱石を並べる。未発見の鉱石はシルエットで表示する。
- 発見数と、各鉱石の所持数、解説文を表示する。
- 標本棚：お気に入りの鉱石を3つまで選んで飾る（ランキングページでフレンドに見える）。

### 4.11 記録（統計）

- 日ごと・週ごとに保存する：採掘回数、獲得ポイント、自分で地上に戻った回数、強制帰還の回数、総スクロール距離、流し読みと判定された距離（流し読み率）。
- ハッカソンの発表で効果を示すために使うので、図鑑ページで推移を見られるようにし、CSVで書き出せるようにする。

## 5. アカウント・フレンド・ランキング

### 5.1 ログイン

- ゲーム本体はログインなしで遊べる。フレンドとランキングを使うときだけGoogleでログインする。
- `chrome.identity` でGoogleのトークンを取得し、Firebase Authentication に `signInWithCredential` でサインインする。Firebase Auth は拡張機能向けの読み込み方（`firebase/auth/web-extension`）を使い、外部コードを読み込まない構成にする。最新の推奨方法は公式ドキュメントで確認すること。
- 開発中に拡張機能のIDが変わらないよう、manifest に `key` を設定する手順を案内すること。
- ログアウトと、アカウント削除（Firestore上の自分のデータを消す）を用意する。

### 5.2 プロフィールとフレンドコード

- 初回ログイン時にニックネームを設定する。他のユーザーに見えるのはニックネームだけで、Googleアカウントの本名、メールアドレス、アイコンは他人に表示しない。
- フレンドコード：8文字。見間違えやすい文字（0とO、1とIとl など）を使わない。重複しないように発行する。
- フレンドは承認制にする。相手のコードを入力すると申請が届き、相手が承認するとお互いにフレンドになる。拒否とフレンド解除もできる。

### 5.3 ランキングページ

- 拡張機能内のページとして作り、タブで開く。
- 自分とフレンドの今週のランキングを表示する。順位の指標は「今週持ち帰った鉱石のポイント合計」。あわせて図鑑の発見数と、自分で地上に戻った回数も表示する。深度やスクロール距離では順位を付けない。
- 週は月曜0時（ローカル時刻）で区切り、ISO週番号で管理する。
- ユーザーを選ぶと、その人の詳細を表示する：
  - 図鑑比べ：地層ごとに自分と相手の発見状況を並べ、「相手だけが持っている」「自分だけが持っている」「両方持っている」を色分けする
  - 相手の標本棚
  - 相手の今週の記録（ポイント、採掘回数、自分で戻った回数）
- フレンド管理：自分のフレンドコードの表示とコピー、コード入力による申請、届いた申請の承認・拒否、フレンド解除。
- ランキングの集計は、ページを開いたときにブラウザ側で行う（Cloud Functions は使わない）。

### 5.4 Firestore のデータとルール

データ構成の案（改善案があれば計画で提案すること）：

- `users/{uid}`：公開プロフィール。`nickname`、`friendCode`、`friendUids`、`collection`（鉱石IDごとの所持数）、`showcase`（標本棚の鉱石ID）、`weekly`（`weekId`、`points`、`mines`、`selfReturns`）、`updatedAt`
- `friendCodes/{code}`：`{ uid }`。コードからユーザーを探すため
- `friendRequests/{requestId}`：`fromUid`、`toUid`、`status`、`createdAt`

セキュリティルールの要件：

- 自分のドキュメントは自分だけが書き込める
- `users/{uid}` は、本人と、`friendUids` に含まれるユーザーだけが読める
- `friendCodes` は、ログイン中のユーザーがコードを指定して1件ずつ読める（一覧の取得はできない）
- `friendRequests` は当事者だけが読み書きできる
- 値の型と上限をチェックする（例：`weekly.points` が、1日の採掘回数の上限から計算できる最大値を超えないこと）
- `firestore.rules` をリポジトリに含める

同期：

- ローカル（`chrome.storage.local`）を正とし、Firestore には集計結果だけを送る。
- 送るタイミングは、地上に戻ったときと、`chrome.alarms` で15分ごと（変化があるときのみ）。無料枠を圧迫しないようにする。
- 受け取ったフレンドのデータが上限を超える不自然な値なら、表示上で印を付ける程度でよい。

## 6. プライバシー

- 見たページのURL、タイトル、本文は保存も送信もしない。
- Firestore に送るのは、ニックネーム、フレンドコード、フレンドの一覧、図鑑の所持数、標本棚、週の集計だけ。
- 「掘った場所」の記録はメモリのみに置く。
- 初回起動時に、何を記録して何を記録しないかを短く説明する画面を出す。

## 7. 権限

- `permissions`：`storage`、`alarms`、`idle`、`identity`（必要なら `downloads`）
- content script の対象：`<all_urls>`。インストール時に強い警告が出るため、6の説明画面で理由を伝える。
- 不要な権限は追加しない。

## 8. 設定値

- 調整が必要な数値は、すべて `src/config.ts` に集める（この文書に出てくる初期値すべて）。
- デモモード：`DEPTH_MULTIPLIER` を大きくする、採掘時間を短くするなど、発表で短時間に見せられる設定に切り替えられるようにする。

## 9. デバッグ表示

- 開発用に、ページの左下などに小さなデバッグ表示を出せるようにする（設定でオン・オフ）。
- 表示内容：直近の平均スクロール速度、流し読み状態、採掘の開始条件それぞれの成否、画面内の文字数の概算、今日の総スクロール距離。
- しきい値の調整に使う。

## 10. 実装フェーズ

各フェーズで、判定ロジック（流し読み判定、採掘の開始条件、抽選、油の計算、週番号の計算など）は純粋な関数にして、Vitest でテストすること。

**Phase 1：土台と計測**
- プロジェクトの雛形（MV3、TypeScript、Vite）
- スクロール計測、流し読み判定、service worker への送信と保存、バッジ表示、デバッグ表示
- 完了条件：いろいろなサイトで、深度の増え方と流し読み判定がデバッグ表示どおりに動く

**Phase 2：採掘とゲームの流れ**
- 採掘判定、地層と鉱石のデータ、油、帰還、画面右端の演出
- 完了条件：記事を読んで止まると鉱石が掘れ、流し読みや放置では掘れない

**Phase 3：ポップアップと図鑑**
- ポップアップ、図鑑ページ、標本棚、記録とCSV書き出し、初回の説明画面

**Phase 4：ログインとフレンド**
- Googleログイン、ニックネーム、フレンドコード、申請と承認、Firestore のルール、同期

**Phase 5：ランキングページ**
- ランキング一覧、ユーザー選択と詳細表示、図鑑比べ

**Phase 6：仕上げ（余裕があれば）**
- 標本棚を画像にして共有する機能、サイトごとの無効化、デモモードの調整、Firebase Local Emulator でのルールのテスト

## 11. 守ってほしいこと

- service worker は止まることがあるので、状態をメモリだけに置かず `chrome.storage` に保存する。ただし保存は頻繁にしすぎず、まとめて書く。
- content script はページの動作を壊さない。エラーをページ側に投げない。
- chrome:// のページ、Chromeウェブストア、Chrome内蔵のPDFビューアでは content script が動かないので、そこで処理が落ちないようにする。
- 外部コードを読み込まない（MV3のルール）。
- Firebase の設定値は `.env` から読み込み、リポジトリに含めない（`.env.example` を用意する）。
